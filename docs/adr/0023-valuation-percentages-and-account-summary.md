# ADR-0023: เปอร์เซ็นต์ใน valuation, สรุปรวมทุกพอร์ต และชนิดราคาใน quote

- **สถานะ:** Proposed (ลงมือแล้วบน branch `feature/dashborad-prices`; เจ้าของโปรเจกต์ยืนยันเมื่อ 2026-11-10 ให้คงแหล่งราคา SIP ล่าช้าและแยกข้อ D เป็นงานถัดไป ส่วนรายละเอียด contract ที่เหลือรอยืนยันตอนตรวจ branch)
- **วันที่:** 2026-11-10
- **เกี่ยวข้อง:** ข้อเสนอจาก frontend `next-frontend-stock/docs/backend-proposal-dashboard-and-prices.md` ข้อ A, B และ C, [ADR-0003](0003-decimal-and-event-replay.md), [ADR-0011](0011-api-and-migration-evolution.md), [ADR-0020](0020-delayed-prices-and-valuation-coverage.md), [ADR-0012](0012-defer-stock-page-and-charts.md)

## บริบท
หน้าเว็บต้องการบอกว่าหุ้นแต่ละตัวกำไรหรือขาดทุนกี่ % และเป็นกี่ % ของพอร์ต ต้องการหน้า dashboard ที่สรุปทุกพอร์ตของผู้ใช้พร้อมกราฟสัดส่วนหุ้น และต้องการติดป้ายชนิดราคาจากข้อมูลแทนข้อความตายตัว frontend ถูกห้ามคำนวณต้นทุนและ P&L เอง (AGENTS.md) และ `GET .../valuation` ทีละพอร์ตทำให้ต้องบวกยอดข้ามพอร์ตที่ฝั่งเว็บ เรียกผู้ให้บริการราคาซ้ำตามจำนวนพอร์ต และไม่มีผู้ตัดสิน `coverage` ของทั้งบัญชี

## ทางเลือกที่พิจารณา
1. ให้ frontend หารและบวกเองด้วยไลบรารี decimal: ไม่มีงาน backend แต่สูตรและกรณี `null` มีสองที่ และขัดข้อกำหนด
2. ส่งอัตราส่วน (`"0.0891"`) แทนหน่วยเปอร์เซ็นต์: ต้องคูณ 100 ที่ฝั่งเว็บอีก และสับสนง่ายกับชื่อ `_percent`
3. endpoint สรุปที่แบ่งหน้า `portfolios`: ยอดรวมยังต้องคิดจากทุกพอร์ตอยู่ดี การแบ่งหน้าจึงไม่ลดงานของ server
4. เพิ่มฟิลด์และ endpoint ใน v1 โดย backend คำนวณทั้งหมด

## การตัดสินใจ
เลือกข้อ 4 ทุกอย่างเป็นการเพิ่มใน `/api/v1` ตาม ADR-0011 ไม่มีตารางหรือ migration ใหม่
- **หน่วย:** ฟิลด์ที่ลงท้าย `_percent` เป็นหน่วยเปอร์เซ็นต์ (`"8.5"` คือ 8.5%) เป็น decimal string ความละเอียดเท่าการหารอื่น (28 ตำแหน่ง, half-even) ไม่ปัด การปัดเป็นหน้าที่ UI
- **`GET .../valuation`:** เพิ่ม `cost_basis` (ต้นทุนคงเหลือรวม ไม่ขึ้นกับราคา) และ `unrealized_pnl_percent` ระดับพอร์ต; ราย position เพิ่ม `unrealized_pnl_percent` และ `weight_percent`
- **`null` ไม่ใช่ 0%:** `unrealized_pnl_percent` เป็น `null` เมื่อไม่มีราคา หรือต้นทุนเป็น 0 (หุ้นที่ขายหมด, พอร์ตที่ไม่ถืออะไร); `weight_percent` เป็น `null` เมื่อ `coverage` ไม่ `complete` หรือมูลค่ารวมเป็น 0 ส่วนหุ้นที่ขายหมดในพอร์ตที่ `complete` และมีมูลค่า ได้ `weight_percent` `"0"` ให้ตรงกับ `market_value` `"0"` ที่มีอยู่แล้ว
- **`GET /api/v1/valuation` (operationId `getAccountValuation`):** สรุปทุกพอร์ตของผู้ใช้ที่ login มียอดรวม, `portfolios` (ยอดของแต่ละพอร์ตพร้อม `coverage` ของตัวเองและ `weight_percent`) และ `allocation` (หุ้นตัวเดียวกันจากทุกพอร์ตรวมเป็นแถวเดียวตาม instrument เฉพาะที่ยังถือ เรียงมูลค่ามากไปน้อย แถวที่ไม่มีราคาอยู่ท้าย พร้อม `quote` และ `unavailable_reason`)
- **กติกา coverage ของบัญชี:** เหมือนพอร์ตเดียวแต่นับทุกพอร์ต: `complete` เมื่อหุ้นที่ยังถือทุกตัวในทุกพอร์ตมีราคา ไม่เช่นนั้นยอดรวม, `unrealized_pnl_percent` และ `weight_percent` ทุกตัวเป็น `null` และ `priced_market_value` เป็นผลรวมเฉพาะที่มีราคา
- **ราคา:** symbol เดียวกันถูกขอราคาครั้งเดียวต่อคำขอ ไม่ว่ากี่พอร์ตถือ และทุกพอร์ตใช้ราคาเดียวกัน
- **ไม่แบ่งหน้า:** `portfolios` ส่งครบทุกพอร์ต เรียงใหม่ไปเก่าเหมือน `GET /portfolios`
- **การอ่านข้อมูล:** สอง statement (พอร์ตทั้งหมดของเจ้าของ และประวัติรายการของทุกพอร์ต) ทั้งคู่กรองด้วย `user_id`; พอร์ตที่ถูกสร้างระหว่างสอง statement ถูกตัดออกทั้งพอร์ต ไม่นับครึ่งเดียว
- **ชนิดราคา:** `quote` เพิ่ม `price_type` (ตอนนี้มีค่าเดียวคือ `delayed_bar_close`) และ `delay_minutes` (15) แหล่งราคายังเป็น SIP ล่าช้าตาม ADR-0020 ไม่เปลี่ยน การเปลี่ยนเป็น `latest` ของ IEX หรือแผนเสียเงินต้องมี ADR ใหม่ที่ทบทวน ADR-0020

## ผลที่ตามมา
- frontend แสดง %, ต้นทุนรวม, กราฟวงกลม และป้ายชนิดราคาได้โดยไม่คำนวณเอง สูตรและกรณี `null` มีที่เดียว
- ผลรวม `weight_percent` อาจไม่เท่ากับ 100 พอดีที่ทศนิยมตำแหน่งท้ายๆ เพราะแต่ละค่าปัดที่ 28 ตำแหน่ง
- `GET /api/v1/valuation` อ่านประวัติรายการทั้งหมดของผู้ใช้ทุกครั้ง และขนาด response โตตามจำนวนพอร์ต ถ้าผู้ใช้มีพอร์ตหรือรายการจำนวนมากต้องทบทวน (จำกัดจำนวนพอร์ต หรือเก็บผลคำนวณ) เฟสนี้ไม่มีเพดานจำนวนพอร์ตต่อผู้ใช้
- เมื่อเพิ่มชนิดราคาใหม่ client ที่ไม่รู้จักค่า `price_type` ต้องแสดงเป็นราคาพร้อม `as_of` ตามกติกา ADR-0011
- กราฟเทียบดัชนี (ข้อ D ของข้อเสนอ) ไม่อยู่ใน ADR นี้ ยังเป็นงานเฟสถัดไปตาม ADR-0012
