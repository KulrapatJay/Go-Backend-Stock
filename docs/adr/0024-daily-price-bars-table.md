# ADR-0024: ราคาปิดรายวันย้อนหลังแบบไม่ปรับ เก็บในตาราง `price_bars`

- **สถานะ:** Proposed (เจ้าของโปรเจกต์ยืนยันเมื่อ 2026-11-11: ฐานราคา `raw`, เก็บในตาราง, ประวัติราว 10 ปี และราคาปัจจุบันยังดึงสดตามเดิม; และยืนยันแบบของขั้น 1-2 หลังตรวจแผน; ยังไม่ลงมือ)
- **วันที่:** 2026-11-11
- **เกี่ยวข้อง:** ข้อเสนอจาก frontend `next-frontend-stock/docs/backend-proposal-logos-and-price-history.md` ข้อ F และ G, [ADR-0012](0012-defer-stock-page-and-charts.md), [ADR-0020](0020-delayed-prices-and-valuation-coverage.md), [ADR-0008](0008-instruments-surrogate-key.md), [ADR-0003](0003-decimal-and-event-replay.md), [ADR-0011](0011-api-and-migration-evolution.md), [ADR-0023](0023-valuation-percentages-and-account-summary.md)

## บริบท
กราฟราคาของหุ้นรายตัว และกราฟมูลค่าพอร์ตกับผลตอบแทนเทียบ SPY/QQQ ต้องใช้ราคาย้อนหลัง ซึ่งระบบยังไม่มี `PriceProvider` มี method เดียวคือ `Quotes` ที่ตอบราคาอ้างอิงล่าสุดจากแท่งรายนาที ADR-0012 กำหนดให้เสนอ timeframe ช่วงประวัติ และ method ของ `PriceProvider` ก่อนลงมือ เอกสารนี้คือข้อเสนอนั้น

ผลตรวจกับบัญชี Alpaca แผนฟรีของโปรเจกต์เมื่อ 2026-11-11 (`GET /v2/stocks/bars`, `timeframe=1Day`, `feed=sip`):
- ย้อนหลังได้ถึง 2016-01-04 (ขอตั้งแต่ปี 2000 แต่แท่งแรกที่ได้คือวันนี้)
- ขอหลาย symbol ในคำขอเดียวได้ (AAPL, SPY, QQQ ช่วง 1 ปี ได้ตัวละ 252 แท่งในหน้าเดียว)
- โควตา 200 requests ต่อนาที จาก header `X-Ratelimit-Limit`
- เลือก `adjustment` ได้ทั้ง `raw`, `split` และ `all`; ราคาปิด AAPL วันที่ 2020-08-27 (ก่อน split 4:1) ได้ 500.04, 125.01 และ 121.15 ตามลำดับ
- `end` ที่ใหม่กว่า now − 15 นาที ตอบ `403 subscription does not permit querying recent SIP data` รวมถึง `end` ที่เป็นวันที่ของวันนี้แบบไม่มีเวลา; `end` = now − 16 นาที ผ่าน
- symbol ที่ไม่มีจริงในคำขอหลายตัวไม่อยู่ในผลลัพธ์และไม่ทำให้ error; ช่วงที่ไม่มีข้อมูล (ก่อน IPO) ตอบ 200 พร้อมรายการว่าง; symbol มีจุด (`BRK.B`) ใช้ได้
- timestamp ของแท่งรายวันคือเที่ยงคืนเวลา New York (`05:00Z` หรือ `04:00Z`)
- ยังไม่ได้ตรวจ: ช่วงตลาดเปิด provider ส่งแท่งไม่สมบูรณ์ของวันนี้หรือไม่ (ตรวจตอน 04:53 เวลา New York ซึ่งตลาดยังไม่เปิด) และแท่ง `1Day` นับเฉพาะ regular session หรือรวมนอกเวลา

## ทางเลือกที่พิจารณา
ฐานการปรับราคา:
1. `split` หรือ `all`: กราฟราคาไม่ตกในวันแตกหุ้น แต่ราคาในอดีตไม่ตรงกับราคาที่ผู้ใช้ซื้อจริง ระบบยังไม่ปรับจำนวนหุ้นตาม split มูลค่าพอร์ตย้อนหลังก่อนวันแตกหุ้นจึงผิด และราคาในอดีตทั้งหมดเปลี่ยนทุกครั้งที่มี split ใหม่ ต้องดึงมาเขียนทับ
2. `raw`: ตรงกับราคาที่ซื้อขายจริงในวันนั้นและตรงกับ `Quotes` ที่ใช้ `raw` อยู่แล้ว แท่งของวันที่ปิดแล้วไม่เปลี่ยน แต่กราฟราคาตกเป็นหน้าผาในวันแตกหุ้น

ที่เก็บ:
1. ดึงสดจาก provider พร้อม cache: ไม่มีตารางใหม่ แต่การเปิดกราฟผูกกับ provider ทุกครั้งที่ cache ว่าง และกราฟผลตอบแทนต้องใช้ราคาทุกวันของทุกหุ้นในพอร์ตต่อคำขอ
2. ตาราง `price_bars`: ตอบจาก DB ได้แม้ provider ล่ม แต่ใช้พื้นที่ Supabase Free และต้องมีวิธีเติมข้อมูล

## การตัดสินใจ
- **timeframe:** 1 วัน เก็บ open, high, low, close และ volume ของแท่งรายวันตามที่ provider ให้ (ยังไม่ได้ยืนยันว่า provider นับเฉพาะ regular session)
- **ฐานราคา:** `raw` ทั้งกราฟราคา (ข้อ F) และการคิดมูลค่าพอร์ตย้อนหลัง (ข้อ G) response ระบุ `adjustment: "raw"`
- **ช่วงประวัติ:** เท่าที่แผนฟรีให้ คือถึงต้นปี 2016 รายการของผู้ใช้ที่เก่ากว่านั้นไม่มีราคาของช่วงนั้น ใช้กติกา `null` กับ `coverage` แบบ ADR-0020 ไม่เติม 0 และไม่ประมาณราคา
- **ที่เก็บ:** ตาราง `price_bars` ใน schema `app` อ้าง `instruments` ด้วย `instrument_id` (ADR-0008) หนึ่งแถวต่อ (instrument, source, วันทำการ) เป็น primary key; `source` (`alpaca` หรือ `demo`) อยู่ใน key เพื่อไม่ให้แท่งเดโมที่ค้างในตารางถูกเสิร์ฟเป็นราคาจริงเมื่อสลับ provider และอ่านเฉพาะแถวของ provider ที่ใช้อยู่ ราคาเป็น `numeric` วันเป็น `date` ตามเวลา New York ไม่ใช่ timestamp เก็บเฉพาะแท่งที่วันที่เก่ากว่าวันปัจจุบันตามเวลา New York (ไม่พึ่งปฏิทินตลาด ราคาปิดของวันนี้จึงขึ้นหลังเที่ยงคืน New York) ตาราง `price_bar_coverage` หนึ่งแถวต่อ (instrument, source) เก็บช่วงวันที่ที่เคยถาม provider แล้ว เพื่อแยกวันหยุดออกจากช่วงที่ยังไม่เคยดึง ช่วงนี้ต้องต่อเนื่องเสมอ: คำขอนอกช่วงดึงตั้งแต่ขอบที่ขอจนชนขอบช่วงเดิม รายละเอียด column, CHECK และ index เสนอพร้อม migration และอัปเดต `schema.dbml` กับ spec ในชุดงานเดียวกัน
- **port:** เพิ่ม method ใน `PriceProvider` ที่รับ symbol หลายตัวกับช่วงวันที่ แล้วคืนแท่งรายวันของแต่ละ symbol แยก "ไม่มีข้อมูลของ symbol นี้" ออกจาก "provider ตอบไม่ได้" แบบเดียวกับ `Quotes` และเพิ่ม repository port สำหรับอ่าน/เขียน `price_bars` signature เสนอในแผนของ milestone ก่อนลงมือ
- **การเติมข้อมูล:** เติมส่วนที่ขาดเมื่อมีคำขออ่าน ไม่ใช้ตัวตั้งเวลา ขั้น 1-2 เติมเฉพาะตอนอ่าน endpoint `bars`; การเติมตามวันของรายการซื้อขายทำพร้อมขั้น 3 ที่ต้องใช้จริง และต้องทำนอก portfolio lock คำขอถึง provider ส่ง `end` เป็น timestamp ที่ไม่ใหม่กว่า now − 15 นาทีเสมอ การเขียนซ้ำต้อง idempotent ด้วย unique constraint; `price_bars` เป็นสำเนาข้อมูลตลาด ไม่ใช่ข้อมูลธุรกิจของผู้ใช้ จึงไม่มี audit event และ GET ที่เติมข้อมูลนี้ไม่ขัดกติกา "GET ต้องไม่เปลี่ยนข้อมูลธุรกิจ"
- **provider ล่ม:** ตอบจากข้อมูลที่เก็บไว้และระบุว่าข้อมูลถึงวันไหน ไม่สลับไปข้อมูลเดโม
- **ราคาปัจจุบันไม่เปลี่ยน:** `Quotes` ยังดึงแท่งรายนาทีล่าช้า 15 นาทีจาก provider ตาม ADR-0020 และไม่บันทึกลง `price_bars` โค้ดของ valuation ไม่ต้องแก้
- **โหมดเดโม:** demo provider ต้องมีชุดราคาย้อนหลังตัวอย่างที่ได้ผลเดิมทุกครั้ง รวม SPY และ QQQ และ response มี `is_demo: true`
- **endpoint:** `GET /api/v1/instruments/{symbol}/bars?from&to` ต้อง login; ช่วงเกิน 3,660 วันตอบ `400 invalid_input`; symbol ที่ไม่มีจริงตอบ `422 unknown_symbol` ตาม mapping เดิม; symbol ที่ยังไม่อยู่ใน `instruments` ถูกตรวจกับ `InstrumentProvider` แล้วบันทึก โดยใช้โควตาเดิม 30 symbol ใหม่ต่อผู้ใช้ต่อชั่วโมง (`429 rate_limited`); คำขอที่ตอบจากข้อมูลที่เก็บไว้ไม่มี rate limit เพิ่ม
- **benchmark:** เก็บราคาของ SPY และ QQQ ด้วยวิธีเดียวกับหุ้นที่มีคนถือ รายการ benchmark ที่อนุญาตกำหนดโดย backend

## ผลที่ตามมา
- กราฟราคาและกราฟผลตอบแทนอ่านจาก DB ไม่ผูกกับ provider ทุกคำขอ และแท่งที่เก็บแล้วไม่ต้องแก้ย้อนหลัง
- กราฟราคาของหุ้นที่แตกหุ้นตกเป็นหน้าผาในวันนั้น และมูลค่าพอร์ตหลังวันแตกหุ้นผิดจนกว่าระบบรองรับ split ในรายการของผู้ใช้ เป็นข้อจำกัดเดิมเรื่อง corporate actions ของเฟส 1 ต้องระบุใน UI/README
- ขนาด: ราว 252 แถวต่อ symbol ต่อปี; 100 symbol × 10 ปี ราว 252,000 แถว ประมาณว่าอยู่ในหลักสิบ MB (ยังไม่ได้วัดจริง) ต้องติดตามขนาดตารางเทียบโควตา Supabase Free
- ราคาปิดรายวันกับราคาอ้างอิงจากแท่งรายนาทีหลังตลาดปิดอาจไม่เท่ากัน ตัวเลขบน dashboard กับจุดสุดท้ายของกราฟจึงอาจต่างกันเล็กน้อย ยังไม่ได้วัดขนาดผลต่างกับข้อมูลจริง
- คำขออ่านกราฟครั้งแรกหลังข้อมูลขาดจะช้ากว่าปกติเพราะต้องเรียก provider ต้องมี timeout; คำขอพร้อมกันที่ขาดข้อมูลเดียวกันอาจเรียก provider ซ้ำ ผลยังถูกเพราะเขียนแบบ idempotent ยอมเสียโควตาเล็กน้อยแทนการเพิ่มตัวกันซ้ำ
- ถ้าภายหลังต้องการกราฟราคาแบบปรับ split ให้เพิ่มเป็นข้อมูลชุดใหม่หรือคำนวณจาก corporate actions โดยไม่เปลี่ยนความหมายของแถว `raw` ที่มีอยู่

## ข้อที่เคยรอตัดสิน
1. ตอบแล้ว (2026-11-11): ไม่แสดงแท่งของวันนี้ เก็บเฉพาะวันที่เก่ากว่าวันปัจจุบันตามเวลา New York การต่อจุดสุดท้ายจาก `Quotes` ยังไม่ทำ
2. ~~การเริ่ม endpoint `bars` ถือเป็นการเริ่มเฟสถัดไปตาม ADR-0012 หรือไม่~~ ตอบแล้ว (2026-11-11): เริ่มงานนี้เพราะต้องการกราฟเทียบดัชนี ADR-0012 ไม่ต้องแก้ เพราะระบุไว้แล้วว่าเฟสถัดไปเริ่มด้วย daily bars แบบ delayed โดยต้องเสนอ timeframe ช่วงประวัติและ method ก่อนลงมือ ซึ่งเอกสารนี้คือข้อเสนอนั้น หน้าหุ้นรายตัวใน frontend ยังไม่เริ่ม
3. ตอบแล้ว (2026-11-11): ข้อ G ใช้ time-weighted return และส่งมอบทีละขั้น เริ่มที่ขั้น 1-2 (price_bars + method ใหม่ + endpoint `bars`) ขั้น 3-4 ต้องมี ADR แยกเรื่องสูตรและ contract ของ performance
4. ตอบแล้ว (2026-11-11): เพดาน 3,660 วัน และ `422 unknown_symbol`
