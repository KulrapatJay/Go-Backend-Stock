# ADR-0005: Argon2id + จำกัดการ hash พร้อมกัน และกติการหัสผ่าน

- **สถานะ:** Accepted
- **วันที่:** 2026-10-14
- **เกี่ยวข้อง:** spec หัวข้อ 10

## บริบท
ต้องเก็บรหัสผ่านให้ทนต่อการเดาเมื่อ DB หลุด บน hosting ฟรีที่มี RAM จำกัด และผู้ใช้ไทยมักพิมพ์รหัสโดยลืมสลับแป้นภาษา

## ทางเลือกที่พิจารณา
1. bcrypt cost 12: ใช้ RAM น้อย แต่ต้าน GPU ได้น้อยกว่าและจำกัด 72 bytes
2. Argon2id (19 MiB, t=2, p=1) + semaphore

## การตัดสินใจ
ใช้ Argon2id พร้อม semaphore `PASSWORD_HASH_CONCURRENCY` (ค่าเริ่มต้น 4) รอคิวไม่เกิน 2 วินาทีแล้วตอบ 503 `server_busy` กติการหัสผ่าน: printable ASCII ไม่มีช่องว่าง ยาว 6–32 ตัว ต้องมีพิมพ์เล็ก พิมพ์ใหญ่ และอักขระพิเศษ ไม่อยู่ใน blocklist รหัสยอดนิยมที่ bundle ไว้ และไม่มีส่วนหน้า @ ของอีเมล Login ของบัญชีที่ไม่มีอยู่ตรวจกับ hash จำลอง

## ผลที่ตามมา
- RAM สูงสุดจากการ hash ราว 4 × 19 MiB และตรวจกติกาได้ชัดด้วย field reasons
- ผู้ใช้เลือกขั้นต่ำ 6 ตัวและ composition rules ซึ่งต่ำกว่า/ต่างจาก NIST SP 800-63B (ขั้นต่ำ 8 และไม่แนะนำ composition rules) ความเสี่ยงจากรหัสสั้นลดลงด้วย blocklist, rate limit และ Argon2id แต่ไม่หมดไป
- ปรับกติกาได้ใน validator เดียวโดยไม่แก้ schema; PHC string เก็บ parameters จึง rehash ได้เมื่อปรับค่า
