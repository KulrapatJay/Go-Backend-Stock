# ADR-0025: มูลค่าพอร์ตรายวันและผลตอบแทนแบบ time-weighted เทียบ benchmark

- **สถานะ:** Proposed (รอเจ้าของโปรเจกต์ตรวจ; ยังไม่ลงมือ)
- **วันที่:** 2026-11-12
- **เกี่ยวข้อง:** ข้อเสนอจาก frontend `next-frontend-stock/docs/backend-proposal-performance-and-indicators.md` ข้อ H, [ADR-0024](0024-daily-price-bars-table.md), [ADR-0020](0020-delayed-prices-and-valuation-coverage.md), [ADR-0023](0023-valuation-percentages-and-account-summary.md), [ADR-0003](0003-decimal-and-event-replay.md), [ADR-0011](0011-api-and-migration-evolution.md), [ADR-0016](0016-database-timeouts-and-retryable-busy.md)

## บริบท
ADR-0024 ตัดสินแล้วว่ากราฟเทียบดัชนีใช้ time-weighted return, ราคา `raw`, benchmark คือ SPY และ QQQ และวันที่ขาดราคาเป็น `null` พร้อม `coverage` แต่ยังไม่ได้กำหนดสูตร กติกาเงินเข้าออก และ contract ระบบมีเฉพาะราคาปิดรายวัน ไม่มียอดเงินสด และรายการซื้อขายมีเวลากับราคาที่ซื้อจริง ข้อเสนอของ frontend ถามแปดเรื่อง เอกสารนี้ตอบทั้งหมด

## ทางเลือกที่พิจารณา
เงินเข้าออกภายในวัน:
1. ทุกรายการนับที่ปลายวัน (`r = (V − F) / V_ก่อน − 1`): วันแรกที่ซื้อหารด้วย 0 และผลต่างระหว่างราคาซื้อกับราคาปิดหายไป
2. ทุกรายการนับที่ต้นวัน (`r = V / (V_ก่อน + F) − 1`): วันที่ขายหมดตัวหารเข้าใกล้ 0 หรือติดลบ
3. ซื้อนับที่ต้นวัน ขายนับที่ปลายวัน (`r = (V + ขาย) / (V_ก่อน + ซื้อ) − 1`): ตัวหารเป็นบวกเสมอเมื่อมีเงินลงทุน และผลต่างราคาซื้อขายกับราคาปิดนับเป็นผลตอบแทนของวันนั้น

ช่วงที่ไม่ถืออะไร: เส้นขาด (`null`) หรือเส้นราบ

## การตัดสินใจ
- **endpoint:** `GET /api/v1/portfolios/{portfolio_id}/performance` และ `GET /api/v1/performance` (รวมทุกพอร์ตของผู้ใช้) ต้อง login query `range` บังคับ เป็นหนึ่งใน `1m`, `3m`, `6m`, `ytd`, `1y`, `5y`, `all`; `benchmarks` ไม่บังคับ เป็นรายการคั่นด้วย comma จาก `SPY`, `QQQ` (ไม่ส่ง = ไม่มี benchmark) ค่าอื่นหรือค่าซ้ำตอบ `400 invalid_input` ขั้น 3 และขั้น 4 ส่งมอบพร้อมกันใน endpoint เดียว เพราะคำนวณจากรอบเดียวกัน
- **สูตร (ทางเลือก 3):** ผลตอบแทนของวัน `r = (V + ขาย) / (V_ก่อน + ซื้อ) − 1` โดย `V` = ผลรวมจำนวนหุ้นที่ถือตอนสิ้นวัน × ราคาปิด `raw`, `ซื้อ` = จำนวน × ราคาซื้อ + ค่าธรรมเนียม, `ขาย` = จำนวน × ราคาขาย − ค่าธรรมเนียม ผลตอบแทนจึงรวมค่าธรรมเนียม และเงินจากการขายเป็นเงินไหลออก ณ ราคาที่ขายจริง ผลตอบแทนสะสมคือผลคูณของ `1 + r` ลบ 1 หารด้วยความละเอียด 28 ตำแหน่ง half-even ตาม ADR-0003 response มี `method: "time_weighted"` และ `fees_included: true`
- **วันของรายการ:** วันที่ New York ของ `executed_at` รายการที่ลงวันที่ไม่มีแท่งราคา (เสาร์อาทิตย์ วันหยุด) นับรวมกับวันถัดไปที่มีมูลค่า
- **จุดเริ่ม:** จุดแรกคือวันแรกในช่วงที่พอร์ตมีมูลค่ามากกว่า 0 และรู้มูลค่าครบ ทุกเส้นเริ่มวันนั้นด้วย `return_percent` `"0"` และ `range.from` บอกวันนั้น เงินเข้าออกของวันแรกไม่นับเป็นผลตอบแทน (ฐานคือมูลค่าปิดของวันแรก) ช่วงก่อน 2016-01-04 ไม่มีแท่งราคาจึงไม่มีจุด เส้นเริ่มที่วันแรกที่มีราคา
- **ช่วงที่ไม่ถืออะไร:** เส้นราบ จุดของวันนั้นมี `market_value` `"0"` และ `return_percent` เท่าค่าสะสมก่อนหน้า เมื่อซื้อใหม่ผลตอบแทนคูณต่อจากค่าเดิม
- **วันที่ขาดราคา:** วันที่หุ้นที่ถืออยู่อย่างน้อยหนึ่งตัวไม่มีแท่ง จุดของพอร์ตเป็น `null` ทั้ง `market_value` และ `return_percent` ไม่ใช้ราคาปิดล่าสุดแทน วันถัดไปที่รู้มูลค่าคิดผลตอบแทนข้ามช่วงที่ขาดโดยรวมเงินเข้าออกของช่วงนั้น `coverage` เป็น `complete` เมื่อไม่มีจุด `null` และการเติมราคาสำเร็จ, `partial` เมื่อมีจุด `null` หรือเติมราคาไม่สำเร็จบางส่วน, `unavailable` เมื่อพอร์ตถือหุ้นในช่วงนั้นแต่ไม่มีวันใดรู้มูลค่าเลย (รายการจุดว่าง) พอร์ตที่ไม่ถืออะไรในช่วงได้ `complete` กับรายการจุดว่าง
- **benchmark:** ผลตอบแทน = ราคาปิดของวันนั้น / ราคาปิดของวัน `range.from` − 1 บนวันชุดเดียวกับพอร์ต วันที่ benchmark ไม่มีแท่งเป็น `null` `excess_return_percent` = ผลตอบแทนพอร์ต − ผลตอบแทน benchmark ณ วันสุดท้ายที่พอร์ตมีค่า เป็นจุดเปอร์เซ็นต์ และเป็น `null` เมื่อฝั่งใดฝั่งหนึ่งไม่มีค่า
- **ช่วงและจำนวนจุด:** จุดเป็นรายวันเสมอ (`interval: "1d"`) ช่วงยาวสุดคือ 3,660 วันตามเพดานของ `bars` (`all` ที่ยาวกว่านั้นถูกตัดเหลือ 3,660 วันล่าสุด) จึงมีไม่เกินราว 2,520 จุดต่อเส้น ยังไม่ลดเป็นรายสัปดาห์ ฟิลด์ `interval` มีไว้ให้เพิ่มค่าอื่นได้ตาม ADR-0011 จุดสุดท้ายคือวันที่ปิดแล้วล่าสุดตามเวลา New York เหมือน `bars`
- **การเติมราคา:** เติมตอนอ่านด้วยกลไกเดียวกับ `bars` นอก DB transaction และไม่ถือ lock ขอ provider ครั้งละไม่เกิน 10 symbol และบันทึกทีละชุด คำขอที่หมดเวลาจึงไม่เสียส่วนที่เติมแล้ว เมื่อ provider ตอบไม่ได้: ถ้าหุ้นที่ต้องใช้ทุกตัวมีข้อมูลเก็บไว้ ตอบ 200 ด้วย `coverage: "partial"` และ `data_through`; ถ้ามีตัวใดไม่มีข้อมูลเลย ตอบ `503 dependency_unavailable` ไม่สลับไปข้อมูลเดโม
- **benchmark ที่ยังไม่อยู่ใน `instruments`:** ตรวจกับ `InstrumentProvider` แล้วบันทึกด้วยกติกาและโควตาเดียวกับ `bars`
- **ไม่เก็บผลคำนวณ:** คำนวณจากรายการและ `price_bars` ทุกคำขอ การแก้หรือลบรายการย้อนหลังจึงมีผลในคำขอถัดไป ไม่มีตารางหรือ migration ใหม่
- **split:** ไม่ตรวจจับในงานนี้ ไม่มีฟิลด์เตือนใน response frontend แสดงคำเตือนคงที่ตามข้อจำกัดของ ADR-0024
- **หน่วยและรูปแบบ:** `_percent` เป็นหน่วยเปอร์เซ็นต์ตาม ADR-0023, ตัวเลขเป็น decimal string ไม่ปัด, `date` เป็นวันที่ตลาด New York เรียงเก่าไปใหม่, `is_demo` มาจาก source ของ provider

## ผลที่ตามมา
- เส้นของพอร์ตกับ benchmark เริ่มวันเดียวกันที่ 0% จึงเทียบกันได้ตรง และการฝากถอน (ซื้อเพิ่ม ขายออก) ไม่ทำให้เส้นกระโดด
- ผลตอบแทนของวันแรกที่ซื้อ (ผลต่างราคาซื้อกับราคาปิด และค่าธรรมเนียมของวันนั้น) ไม่อยู่ในเส้น เมื่อจุดเริ่มคือวันซื้อครั้งแรก
- มูลค่าพอร์ตหลังวันแตกหุ้นผิดจนกว่าระบบรองรับ split (ข้อจำกัดเดิมของ ADR-0024) และผลตอบแทนไม่รวมเงินปันผล ทั้งของพอร์ตและของ SPY/QQQ
- คำขอแรกของพอร์ตที่มีหุ้นมากและช่วงยาวอาจเติมราคาไม่ทัน deadline 12 วินาทีของคำขอ (ADR-0016) จะได้ `partial` หรือ 503 แล้วคำขอถัดไปเติมต่อจากเดิม ยังไม่ได้วัดเวลากับพอร์ตจริง
- response ของช่วง 10 ปีพร้อมสอง benchmark มีราว 7,500 จุด ยังไม่ได้วัดขนาดจริง ถ้าใหญ่เกินให้เพิ่ม `interval: "1w"` ภายหลัง
- ทุกคำขออ่านประวัติรายการและแท่งราคาของทุกหุ้นในช่วง ถ้าช้าต้องทบทวนการเก็บผลคำนวณ

## ข้อที่รอตัดสิน
1. ยืนยันสูตรทางเลือก 3 และการไม่นับผลตอบแทนของวันแรก
2. ตัวชี้วัดทางเทคนิค (ข้อ I RSI และข้อ J แนวรับ/แนวต้านของข้อเสนอ) ไม่อยู่ใน ADR นี้ ต้องยืนยันว่าเป็นงานของเฟสถัดไป แล้วเขียน ADR กับแผนแยก
